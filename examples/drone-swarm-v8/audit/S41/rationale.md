## What was decided

Alternative 2 is the drone-centric physical architecture, genuinely different from a ground-centric split: it keeps the same LA member definition, fleet multiplicity and functions, but re-decides where coordination executes. The 8 #Coordination functions are split by what CV-16 calls "the architecture decision": deconflictFlight and relayThroughNeighbour are things every member does for itself, so they are allocated to the fleet; handOverSector, rotateRecharge, redistributeCoverage, correlateTracks, handOverTrack and admitMember are things one member decides for the others, and here that decision is put onboard an elected representative (droneA, typed by a CoordinatorDroneNode variant that also carries the ground-link radio) rather than on the ground — six of eight, comfortably over half. The 5 #C2 functions keep their ground usage (allocated to the ground station's nested logical control part) in this alternative too, as required of both. Physically: every drone is a #Node part def (DroneNode) that hosts the LA #Member part def SurveillanceDrone by nesting (CV-06); the mesh radio and ground radio are themselves #Node parts, never actors; the population's representative-to-representative link is a connection typed by a new connection def (RFMeshLink) carrying the same meshOut/meshIn ports the member already declares, so the member definition, the fleet's [12] multiplicity and a typed link between two named representatives all survive into PA. Resource budgets (flight endurance, turnaround, footprint) are restated as local valued attributes with require constraints, per CV-17, since a constraint body cannot reach Common. areaUnderWatchFraction is deliberately left without a literal and derived by an assert constraint from those local attributes (12 drones × airborne-share × footprint ÷ area of interest ≈ 0.96), satisfying the checked rule that a share held "at any moment" cannot simply be asserted larger than the population's airborne share without justification; coverageUnderMeshJammingFraction is derived from it with a resilience factor reflecting this alternative's distributed coordination. Two new hazards are added for the technology this alternative introduces (a single onboard coordination node as a point of failure, and mesh-radio hardware failure distinct from interference) and mitigated by the fleet's uniform-member capability and the recovery point respectively; a third (battery-contact wear) is tagged #Accepted with its reason. The eight brief-named hazards are satisfied here by this alternative's own physical components (fleet, the representative, or the ground station), not only by the LA function they share with alternative 1.

## Repair 3

The only real defect was a tag-placement parse error, repeated three times: `state def DroneMode #Mode { ... }`, `state def DroneState #State { ... }` and `state def FleetConfiguration #Configuration { ... }` put the `#Tag` AFTER the `state def <Name>` instead of before the keyword, which this dialect requires (`#Tag state def Name { ... }`, mirroring the already-correct `#Node part def X { ... }` and `#Member part def X { ... }` elsewhere in the same fragment). The parser choked on the first occurrence at "state def DroneMode #Mode {" (line 203: it expects the declaration to close, not to see `{` after the stray `#Mode`), recovered by closing scopes early, and then hit the same malformed pattern again at "state def DroneState #State {" (line 286), producing the `no-viable-alt` on `#`. Because the checker's line-based scope-closing recovery discarded everything structurally downstream of the first break, all of the CV-16 population elements (member def, fleet multiplicity, representatives, peer link), the 17-function allocation block, the 8 coordination-on-members allocations, all 12 #Estimate measures, the 5 brief-named modes, and the layer's #Hazard package/satisfy lines were reported as absent even though they are present later in the same fragment — they simply were never reached as valid PA content. Fixing the three tag placements (`#Mode state def DroneMode {`, `#State state def DroneState {`, `#Configuration state def FleetConfiguration {`) removes the parse break and lets the parser reach every element that was already correctly written afterward: the member population (SurveillanceDrone/fleet[12]/memberA/memberB/meshPeerLink typed by RFMeshLink), all 17 function allocations (with all 8 #Coordination functions on fleet/memberA/memberB, satisfying the "at least half on members" alternative-2 rule, and every #C2 function keeping a groundStation usage plus recallToLand also reaching the fleet), all 12 #Estimate measures (with the two population-share measures correctly left without a literal and derived via assert constraint from PhysicalBudgets valued attributes, per the checked CV-17 case), the five brief-named modes/configuration states, the four checked PropertyPattern rules on DroneMode, and the layer's own two #Hazard requirements (one #Accepted) plus its satisfy statements for all ten hazards named by SA/LA and this layer's own two. No other content was changed, and no new Common types were needed, so commonAdditions is empty.
