# S10

## What was decided

Modeled OA as: (1) seven brief stakeholders as #Actor part defs + one usage each (DutyController, Analysts, OperationsCentre, AirspaceAuthority, GroundCrew, FixedCameraNetworkOwner, ProgrammeSponsor); (2) the population the system takes over as part def WatchAssetPopulation (untagged, distinct name to avoid any collision with the system name) with exactly two representative usages named `watchAsset` (the exact brief-mandated name, untagged) and `watchAssetPeer`; (3) all 13 brief-named coordination/C2 functions as capitalised, tagged action defs (#Coordination x8, #C2 x5); (4) every operational activity as a package-level action usage typed by one of these defs (or a plain core def), each carrying its own ports, so every CV-05 flow is the required two-level `<action>.<port>` form; (5) explicit `allocate <activity> to <entity>;` for every one of the 44 activities, so allocation is unambiguous rather than inferred from nesting; (6) the ten brief capabilities as #Capability use case defs, each with a typed `subject`, plus one #Mission use case def; (7) two state defs on WatchAssetPopulation (#Mode WatchAssetMode covering Watching + the five brief-named degraded/quarantined/landed conditions, #State WatchAssetStatus for coarse platform status), both fully reachable, inherited by both representatives via typing so they aren't redeclared. Both representatives get their own instance of every coordination def (initiator role on one side, receiver on the other, alternating across the two so both directions of the population's 8 named coordination functions are shown), giving genuine peer-to-peer flows plus a ground-crew recharge exchange. Followed the advisor's structural corrections: flattened all activities to package scope (no three-level paths), gave every broadcast a dedicated out port per destination (one flow per port, satisfying connector-endpoint hygiene), and treated `Common` as already carrying the brief's named item definitions (DetectionReport/Track/DecisionRecord and the environment I/O items), referencing them as `Common::X` rather than redeclaring them — only `CoordinationMessage`, which is internal to OA-level coordination and not named as a system boundary item in the brief, is added via commonAdditions, deliberately attribute-free to avoid unresolved base-type questions.

## Repair 1

The checker flagged 21 unresolved-type-ref errors, all for the same five item types (DetectionReportsAndTracks, ReportAcknowledgements, DecisionRecords, SupervisoryAndRecallCommands, CameraNetworkTracks) used consistently across watchAsset's, watchAssetPeer's, and the other entities' ports and flows. Every reference itself is structurally correct — each flow end resolves to a real action/port pair, and every referenced feature exists on the naming side — the problem is purely that package Common never declared these five item definitions. Per instructions, rather than deleting or renaming the references (which would break already-passing flow/port resolution and the population-exchange requirement), I declare the five missing item defs in commonAdditions, each with a doc so it satisfies doc coverage. The four other Common types the fragment uses (StatusPicture, MissionTasking, CoordinationMessage, Track) were not flagged, meaning Common already declares them, so they are left alone and not redeclared (avoiding a duplicate-definition fault). The OA fragment itself is otherwise unchanged: no renames, no structural edits, since none of the checker's structural findings (flow ends, allocations, reachable modes, capability subjects) were faulted.

## Deliberately left for later

- Hazards (PositionDriftHazard, MeshJammingHazard, MisclassificationHazard, SensingDegradedUnnoticedHazard, StaleTrackHazard, SpoofedMemberHazard, MixedClassifierVersionsHazard, OperatorOverloadHazard) are explicitly SA::Hazards per the brief's Rules/Hazards section — not modeled here; SA must state and satisfy them.
- The four #Rule requirements (RecallWins, ReturnsWhenIsolated, GeofenceBreachEndsWatch, QuarantinedStaysOut) with their PropertyPattern annotations are stated once at SA on the member's machine — not added here; SA should reuse the state names already declared in WatchAssetMode (Watching, Isolated, Quarantined, Landed) for its q/r/p attributes.
- MeshDegraded is named 'of the fleet' in the brief; OA has no fleet-level part (only two member representatives), so it was placed on the member's own #Mode machine (WatchAssetMode) instead. SA/LA should confirm whether a fleet-level state def is also wanted once the fleet part exists, or whether this member-level placement is treated as the authoritative one.
- Numeric MOEs (areaUnderWatchShare, reportLatencySeconds, etc.) were not written as require constraint blocks here since the option note says they never block this layer and they read more naturally once SA/PA have the parts to attach budgets to.
- MovingObjectsInArea and AirspaceClearance have no explicit OA flow/actor: the real world and the airspace authority's limits are not exchange partners in the OA sense the brief's stakeholder list supports. DetectAndClassifyObjects and StayWithinClearedAirspace carry them only in doc. SA should formalise these as system boundary ports when the system is introduced.
- MeshRadio, GroundLinkRadio, StoredMaps and RechargePointAndGroundCrew (the brief's 'resource' entries) were deliberately not reified as OA parts — they are how coordination/navigation/recharge happen, which is LA/PA's job per CV-16 ('carried by MeshRadio' is explicitly a from-LA-down detail); OA only shows the coordination and recharge exchanges themselves, medium-agnostic.
- commonAdditions assumes Common already declares MissionTasking, SupervisoryAndRecallCommands, MovingObjectsInArea, CameraNetworkTracks, ReportAcknowledgements, DetectionReportsAndTracks, StatusPicture, DecisionRecords, DetectionReport, Track and DecisionRecord (per the brief's 'What the items carry' section, phrased as already describing Common, and per the given MeshPort/MeshLink precedent). If assembly shows Common does not yet have these, they need to be added at load time — flag this back rather than silently duplicating.
