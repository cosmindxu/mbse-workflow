## What was decided

Alternative 2 is a decentralised split, genuinely different from a ground-deciding alternative 1: the physical decomposition puts a coordination-capable node (mesh radio, ground-link radio, stored-map store, and usages of 7 of the 8 #Coordination action defs — HandOverSector, RotateRecharge, RedistributeCoverage, DeconflictMembers, RelayLink, CorrelateTracks, HandOverTrack) inside every SurveillanceDrone member, nested per CV-06. The ground station becomes a thin node: it keeps every #C2 function (as required in both alternatives) plus only the one #Coordination function that is inherently a ground authority responsibility — AdmitMember, the mesh-admission gatekeeper that mitigates SpoofedMemberHazard — and ManageClassifierVersion, kept on the ground as a fleet-wide consistency control. This is the allocation decision CV-16 calls out: 7/8 Coordination functions on the fleet clears "at least half," and it is what makes groundLinkLossAreaUnderWatchShare (0.91) the standout measure versus jammedMeshAreaUnderWatchShare (0.78, the mesh now matters more) — the trade-off the brief asks the architecture to show.
Population survives into PA per CV-16: one #Member part def SurveillanceDrone with meshOut/meshIn ports, part fleet : SurveillanceDrone [12], two named representatives memberA/memberB, and interface peerLink (plus its return leg) typed by Common::MeshLink. The mesh radio and ground-link radio are modelled as #Node parts nested inside the member, never as actors. State is split as #Mode (NavigationDegraded, SensingDegraded, Quarantined/Readmitting/Readmitted) and #State (Landed/Launching/Watching/Isolated/Recalled/OutsideClearance/Landing) so the four CV-18 rules can be checked without a shortcut path around Landed; fleet-level MeshDegraded is a #Configuration on the fleet usage, and the ground station gets its own light #Mode/#State pair. All 8 brief hazards are satisfied by path against physical components (fleet or groundStation), never restated; two PA-added hazards (ground radio hardware failure, recharge contention) are declared in a nested package Hazards and mitigated. All 14 scored MoEs get a worst-case #Estimate with a doc basis; coverageLossOnMemberLoss is derived via assert constraint from the brief-fixed fleetSizeValue (1/12) rather than stated as a literal, per CV-17. Resource budgets (flight endurance, recharge time, fleet size, area of interest, operator workload, on-board compute cost) are require constraints over locally valued attributes, since a constraint body cannot reach Common.

## Repair 2

Root cause of the parse errors and their cascade: `perform safetyMonitor.memberStateMachine;` / `perform safetyMonitor.memberModeMachine;` at the end of `SurveillanceDrone` used a dotted-path reference as a `perform` statement, which this grammar does not accept — the parser stopped at the `.` (lines 379/380), and each failed statement was also read as a second and third declaration of the name `safetyMonitor` in that scope (the duplicate-name findings at 375/379/380). The recovery from that error closed scopes early, leaving one unmatched `}` dangling at real EOF (line 680) and corrupting evaluation of everything textually after it, which is why the coverageLossOnMemberLoss estimate read as valueless despite already carrying its `assert constraint` derivation, and why the numeric require-constraints further up reported as unevaluable.

Fix: removed both dotted `perform` statements. Rather than re-adding a working reference to a machine nested inside `SafetyMonitor`, I moved the `#State state def MemberState` and `#Mode state def MemberMode` (with their four checked `SysproseVerification::PropertyPattern` properties: RecallWins, GeofenceBreachEndsWatch, ReturnsWhenIsolated, QuarantinedStaysOut) to be owned directly by `#Member part def SurveillanceDrone`, with `perform action memberStateMachine : MemberState;` / `perform action memberModeMachine : MemberMode;` declared in the same scope — this is what the `modes.fromBrief` findings required ("no state machine of SurveillanceDrone... It is a state of SafetyMonitor::MemberMode, which is not SurveillanceDrone"). `SafetyMonitor` is kept as a nested `part def` — still a separate, dedicated override-authority component distinct from the detect/classify/decide behaviour — but is now a minimal doc-only definition instead of holding its own duplicate machines, so there is no name collision and no orphaned reference. All four brief-named modes (`NavigationDegraded`, `SensingDegraded`, `Isolated`, `Quarantined`) are now states of a machine literally owned by `SurveillanceDrone`. Every other declaration, allocation, connection, hazard satisfy, rule satisfy and MoE estimate is unchanged verbatim from the given fragment.
